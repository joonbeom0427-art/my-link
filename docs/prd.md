# 📄 마이링크 (My Link) - 제품 요구사항 정의서 (PRD)

본 문서는 개발자와 크리에이터를 위한 멀티 링크 페이지(Link-in-bio) 서비스 **“마이링크 (My Link)”**의 제품 요구사항 정의서(Product Requirement Document)입니다. 제공할 핵심 가치와 구체적인 기술적/기능적 요구사항을 정의합니다.

본 문서는 `docs` 폴더 내에 배치되며, 추후 작성될 **사용자 시나리오(User Scenarios)** 및 **와이어프레임(Wireframes)** 문서의 기준점이 됩니다.

---

## 1. 프로젝트 개요 (Project Overview)

### 1.1 프로젝트명
* **국문**: 마이링크
* **영문**: My Link
* **서비스 슬로건**: "개발자와 크리에이터의 모든 활동을 단 하나의 링크에 담다."

### 1.2 프로젝트 목적
개발자와 크리에이터는 GitHub, 기술 블로그(Velog, Tistory, Medium), 개인 포트폴리오, 유튜브, 소셜 미디어(X, LinkedIn) 등 다채로운 채널에서 페르소나를 전개합니다. 하지만 소셜 플랫폼의 프로필 영역은 보통 단 하나의 링크만 허용합니다. 

**마이링크**는 이러한 테크니컬 유저와 창작자를 위해, 분산된 모든 디지털 흔적을 **모던하고 세련된 단 하나의 고유 URL**로 통합·시각화하는 최적의 멀티 링크(Link-in-Bio) 솔루션을 제공합니다.

### 1.3 대상 사용자 (Target Audience)
1. **개발자 (Developers)**:
   * 자신의 GitHub 리포지토리, 기술 블로그, 포트폴리오 사이트, 사이드 프로젝트 결과물을 깔끔하게 공유하고 싶어 하는 엔지니어.
   * 복잡하고 화려한 꾸미기보다는 정돈된 레이아웃, 코드 블록 친화적인 디자인, 기술 중심적 컴포넌트를 선호하는 테크니컬 유저.
2. **크리에이터 (Creators)**:
   * 유튜브 채널, 기술 뉴스레터(Stibee, Substack), 강의 플랫폼(Inflearn), 후원 서비스(Toss, Buy Me a Coffee) 등을 일원화하여 연동하려는 창작자.
   * 독자 및 구독자와의 접점을 극대화하고자 하는 1인 퍼스널 브랜딩 운영자.

## 3. 기능 상세 설명 (Detailed Feature Specifications)

### 3.1 회원 및 계정 (User Accounts)

#### F-1.1: Firebase 기반 Google 소셜 로그인 (필수)
* **기능 사양**:
  * **인증 시스템**: **Firebase Authentication**을 도입하여 보안성과 신뢰성을 극대화합니다.
  * **인증 수단**: 가입 장벽을 낮추기 위해 **Google 소셜 로그인 단일 방식**만 제공하여 복잡한 회원가입 절차(이메일 인증, 비밀번호 찾기 등)를 생략합니다.
  * **온보딩 절차**: 
    * 구글 최초 로그인 완료 시 즉시 고유 주소로 사용할 `username` 설정 화면으로 이동합니다.
    * `username`은 고유 식별자 역할을 하며, 영어 소문자, 숫자, 하이픈(`-`), 언더바(`_`)만 허용합니다. (중복 검사 필수)

#### F-1.2: 프로필 설정 (필수)
* **기능 사양**:
  * **프로필 이미지**: 사용자는 이미지를 자유롭게 업로드할 수 있으며, 기본값으로 Google 계정의 프로필 이미지를 불러와 설정 편의성을 높입니다.
  * **프로필명 / 닉네임**: 대외적으로 노출될 이름을 입력합니다. (최대 30자)
  * **바이오 (Bio) 및 태그**: 
    * 소개글(최대 150자) 작성을 지원합니다.
    * 개발자와 크리에이터를 위해 **기술 스택 혹은 전문 분야 태그**(예: `#React`, `#Nextjs`, `#Design`, `#YouTube`)를 배지 형태로 추가할 수 있도록 지원합니다.

---

### 3.2 고유 페이지 및 랜딩 뷰 (Public Landing Page)

#### F-2.1: 고유 URL 생성 및 연결 (필수)
* **기능 사양**:
  * 선점한 `username`을 기준으로 `mylink.at/{username}` (혹은 설정한 도메인의 서브디렉토리 주소)로 접속 가능한 고유 가상 주소가 부여됩니다.
  * 렌더링 최적화를 진행하여 비로그인 사용자 및 검색 로봇이 접속할 때 초고속으로 해당 개발자/크리에이터의 프로필을 서빙합니다.

#### F-2.2: 공개 랜딩 뷰 (필수)
* **기능 사양**:
  * **Shadcn/ui 기반 컴포넌트**: 디자인의 높은 마감도를 보장하기 위해 기본 컴포넌트 셋을 **Shadcn/ui**로 정형화합니다.
  * **모바일 퍼스트 반응형**: SNS 프로필을 통한 모바일 유입이 90% 이상임을 감안하여 세로 폭에 특화된 스마트폰 웹 뷰를 설계하고, 테블릿 및 PC에서도 레이아웃이 무너지지 않도록 그리드를 조정합니다.

---

### 3.3 링크/블록 관리 (Link & Block Management)

#### F-3.1: 링크 추가/수정/삭제 (필수)
* **기능 사양**:
  * 개발자/크리에이터가 자신을 나타내는 주요 채널의 링크를 등록하는 핵심 CRUD입니다.
  * **링크 제목**: 버튼 위에 굵게 노출될 텍스트 (최대 50자, 예: '개발 블로그 구경하기 💻')
  * **이동 주소 (URL)**: 유효한 웹 주소 형식인지 확인합니다.
  * **링크 아이콘 자동 파비콘(Favicon) 연동**: 
    * 사용자가 URL을 등록하면, 해당 URL 도메인의 **파비콘(Favicon)**을 자동으로 분석하여 버튼의 대표 아이콘으로 지정합니다. (예: `github.com` 경로 등록 시 버튼 왼쪽에 GitHub 파비콘 노출)
    * 파비콘은 외부 API(예: Google Favicon Service 등) 또는 해당 도메인의 `shortcut icon` 메타태그에서 실시간 추출해 적용합니다.
    * 사용자가 원할 경우 기본 Lucide Icon이나 수동 아이콘으로 대체할 수 있는 옵션을 함께 고려합니다.
  * **노출 토글 (Show/Hide)**: 링크를 보관하되, 일시적으로 랜딩 페이지 노출을 중단할 수 있는 상태 값 스위치를 제공합니다.

#### F-3.2: 링크 순서 변경 (필수)
* **기능 사양**:
  * 관리 대시보드 내에서 손쉽게 링크 순서를 조정할 수 있도록 드래그 앤 드롭(DnD) 메커니즘을 지원합니다.
  * Shadcn/ui 및 React DnD 라이브러리와 유기적으로 결합하여 매끄러운 햅틱 감성과 모션 효과를 보장합니다.

#### F-3.3: 개발자/SNS 바로가기 아이콘 링크 (필수)
* **기능 사양**:
  * 공개 페이지 최하단(또는 프로필 영역 아래)에 정렬될 아이콘 단축 링크 목록입니다.
  * **개발자 및 크리에이터 특화 지원**: GitHub, LinkedIn, X(구 Twitter), Velog, Medium, YouTube, Twitch 등.
  * 입력 시 Lucide Icons 기반의 정교하고 현대적인 브랜드 로고 아이콘이 자동 배치됩니다.

---

### 3.4 디자인 & 커스텀 (Design & Customization)

#### F-4.1: Shadcn/ui 기반 디자인 시스템 연동 (필수)
* **기능 사양**:
  * 서비스 전반에 **Shadcn/ui 및 Tailwind CSS**의 디자인 토큰 시스템을 주입합니다.
  * **다크 모드 지원**: 개발자 유저들의 선호도가 높은 완벽한 시스템 다크 모드(Dark Mode)를 첫 릴리즈부터 내장 지원합니다.
  * **기본 테마 프리셋**: Shadcn/ui의 기본 색상 테마(Slate, Zinc, Neutral, Stone, Amber 등)와 유려한 보더 반경(Radius)을 조합한 프리셋 테마를 적용할 수 있게 구성합니다.

#### F-4.2: 고급 레이아웃 커스텀 (선택)
* **기능 사양**:
  * **컴포넌트 둥글기 강도 조절**: Shadcn/ui CSS 변수를 활용하여 모서리의 둥글기 반경(`border-radius`)을 미세하게 조정(Sharp, Mid, Full)할 수 있습니다.
  * **브랜드 메인 컬러 커스텀**: 단색 혹은 심플한 투톤의 포인트 컬러를 변경할 수 있도록 테마 변수를 바인딩합니다.

---

### 3.5 블록 확장 기능 (Rich Blocks - 선택)

#### F-6.1: 미디어 및 외부 플랫폼 임베드 블록
* **기능 사양**:
  * **GitHub 잔디(Contribution) 위젯**: 개발자 전용 기능으로, 본인의 GitHub 유저네임을 입력하면 잔디밭 현황 이미지를 동적으로 불러와 프로필 내에 예쁘게 띄워 줍니다.
  * **유튜브 영상 임베드**: 최신 영상 혹은 대표 영상을 랜딩 뷰에서 직접 볼 수 있도록 모바일 화면 비율에 맞춰 반응형 iframe 플레이어를 제공합니다.

#### F-6.2: 후원 및 문의 블록
* **기능 사양**:
  * **커피 후원 (Buy Me a Coffee / Toss) 연동**: 크리에이터와 개발자가 지속적인 창작 지원을 받을 수 있도록 후원 플랫폼 단축 링크를 돋보이게 하는 특별한 후원 컴포넌트를 삽입합니다.

### 3.6 통계 및 분석 (Analytics - 추후 구현 예정)

#### F-5.1: 방문자 및 클릭수 분석 (Phase 2)
* **기능 사양**:
  * **구현 보류**: 첫 릴리즈(MVP) 버전에서는 구현을 보류하고, 서비스 안정화 이후 Phase 2에서 구현을 진행합니다.
  * **향후 구현 스펙**:
    * **방문 통계**: 내 마이링크 프로필의 일별/주별 방문 횟수 측정.
    * **클릭 통계**: 개별 링크 버튼의 클릭 횟수 및 클릭률(CTR) 통계 대시보드 시각화.
    * **데이터 수집**: 경량 웹 분석 도구(예: Vercel Analytics, Google Analytics 등) 또는 맞춤형 클릭 트래킹 미들웨어 연동 예정.

## 4. 비기능적 요구사항 (Non-Functional Requirements)

1. **디자인 마감도 (Shadcn/ui 기반)**:
   * 모든 폼 입력창, 다이얼로그, 토글, 툴팁 등은 Shadcn/ui 디자인 규칙을 철저히 따라 극도의 미니멀리즘과 전문적인 인상을 구현합니다.
2. **인증 안정성 (Firebase Auth)**:
   * 사용자의 세션 정보 관리 및 토큰 보안을 위해 Firebase Client SDK를 견고하게 구현하며, 비인증 사용자의 관리 페이지 접근 시 확실한 차단 및 로그인 페이지 리다이렉트 미들웨어를 구축합니다.
3. **로딩 속도 (Page Performance)**:
   * Next.js의 하이브리드 웹 프레임워크 기능(ISR/SSR)을 백분 활용하여 공개 프로필 렌딩 속도를 1초 안팎으로 제어하며, 모바일 터치 감도를 최대화합니다.
